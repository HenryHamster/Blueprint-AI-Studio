# Blueprint — A Multimodal AI Developer & Secure Execution Sandbox

## Executive Summary
Blueprint is an interactive, AI-powered developer tool that transforms messy human creativity into secure, deployable code. It bridges the gap between highly interactive, multimodal "Google Experiments" and zero-trust cloud infrastructure. Users draw UI wireframes or system architectures on a shared digital canvas. A multimodal Vision-Language Model (VLM) and image generation pipeline interpret these unstructured visual designs, generate high-fidelity mockups, and compile them into structured software tasks. These tasks are then asynchronously executed by autonomous AI coding agents operating inside dynamically provisioned, deeply sandboxed Virtual Machines.

## 1. The Frontend: Multimodal Canvas & Vision Compiler (The Creative Layer)
Inspired by Google’s interactive AI experiments, the frontend replaces the traditional text-based CLI with a rich, interactive whiteboard.
- **Instant Interactivity**: Users sketch UI components directly on the canvas or type a description. Using Nano Banana 2 (Gemini 3 Flash Image), the system provides instant feedback by transforming rough sketches into clean, high-fidelity UI mockups right on the screen. The user is able then to annotate the mockup or provide notes directly on the canvas and iterate with the model.
- **Vision Compilation**: Once the user is satisfied, they click "Deploy." Using the Gemini 1.5 Pro API (via Google AI Studio), the system acts as a "Vision Compiler," analyzing the finalized mockup to understand spatial relationships and UI hierarchy, translating the visual input into a structured JSON blueprint.

## 2. The Backend: Secure Orchestration & State Management (The Infra Layer)
To safely grant autonomous AI agents the ability to write and test the code generated by the blueprint, the backend enforces a strict "assume breach" security model.
- **The Orchestrator (Cloud Run)**: A serverless FastAPI control plane receives the JSON blueprint and Cloud Storage URIs (of the drawings) from the frontend, breaking them down into granular developer tasks.
- **The State Layer (AlloyDB)**: Direct agent-to-agent or agent-to-host network communication is disabled. Instead, AlloyDB acts as a secure, asynchronous Kanban board. It holds the state of the project, queues up coding tasks, and safely manages the shared context.

## 3. The Execution Environment: Zero-Trust Sandboxes & Visual Self-Correction
Autonomous coding agents inherently require the ability to run arbitrary code (e.g., npm install, node script.js), creating massive security vulnerabilities if run locally.
- **Ephemeral VMs (Compute Engine)**: The Cloud Run orchestrator dynamically spins up isolated, ephemeral Virtual Machines using a pre-baked custom OS image.
- **The Visual Feedback Loop**: A worker agent boots up inside the VM, pulls its assigned UI task and the original reference image from AlloyDB. It writes the React code, renders it locally using headless Playwright, and takes a screenshot of its own work. It then sends both the reference image and its own screenshot to Gemini to ask: "Does my coded UI match the user's drawing? If not, what CSS do I need to fix?"
- **Security & Cleanup**: If the agent hallucinates a destructive command, the host infrastructure remains isolated. Once the code is pushed (or if the VM times out), the instance triggers a dead-man's switch and permanently deletes itself.

## 4. Minimum Viable Product (MVP) Scope & Constraints
To ensure feasibility, budget safety, and rapid development, the MVP strictly adheres to the following constraints:
- **Frontend Scope**: The drawing interface will be implemented using an off-the-shelf library (e.g., tldraw) to avoid wasting time on raw canvas engineering.
- **Output Scope (The "Full-Stack Fallacy" constraint)**: The MVP will only generate standalone Frontend UI components (React/Tailwind). The agent will not be tasked with provisioning backend databases, writing Express APIs, or handling authentication logic.
- **Infrastructure Boot Latency**: To prevent 5+ minute wait times, worker VMs will not install dependencies at runtime. A custom Google Compute Engine image will be pre-baked with Node.js, Playwright, and the agent base-code so VMs boot and execute within 60 seconds.
- **Budget & Orphaned Infrastructure**: All Compute Engine VMs will have a hardcoded 1-hour maximum lifecycle and a local sudo shutdown script upon task completion to prevent infinite loops from draining the $250 budget.
- The database layer will utilize AlloyDB Omni (running locally via Docker) to simulate enterprise cloud DB interactions without incurring managed cloud database costs.
